# MonsanUI Project Context

MonsanUI is the private Svelte 5 visual and interaction library for the Monsan suite. Koalify, Manki and Owlth must be built from MonsanUI components and tokens.

Use this file as compact context for another AI/chat. Use `README.md` for setup and operational commands. Use workspace root `AGENTS.md` as the canonical implementation rules.

## Non-Negotiable Rules

- MonsanUI is the visual source of truth.
- Consumer apps must not locally restyle MonsanUI components.
- If a consumer needs a visual change, add a component or prop in MonsanUI first.
- Svelte 5 only.
- pnpm only.
- Strict ESLint and Prettier.
- a11y must be built into components.
- Component APIs must be stable and intentional.
- **AI execution prohibition:** no AI agent may start, run, preview or serve
  MonsanUI or any Monsan Suite project. This includes `pnpm dev`, `dev:fast`,
  `dev:fresh`, `preview`, `start`, `vite dev`, local app servers and any command
  that launches Owlth or another supporting project. Only the user may start
  project processes or perform manual browser/SSO validation.

## Responsibilities

- Export shared Svelte components.
- Export shared CSS through `monsan-ui.css` and `variables.css`.
- Own base normalize, tokens, layout primitives and app shell patterns.
- Provide icons used by suite apps.
- Provide question/input components used by Koalify.
- Provide deck/card/study primitives used by Manki.
- Provide strict consumer standards checkers.
- Provide tooling standards checkers.

## Stack

- SvelteKit with Svelte 5.
- TypeScript.
- Svelte package output.
- Publint.
- Static showcase app.

## Consumer Contract

Consumers install MonsanUI from the private GitHub repository and import:

```ts
import 'monsan-ui/monsan-ui.css';
```

Consumers import components from package exports:

```ts
import { Button, Stack, Alert } from 'monsan-ui';
```

Consumers should use layout primitives before app-owned CSS:

- `AppShell`
- `AppHeader`
- `ContentRegion`
- `ResponsiveGrid`
- `Stack`
- `Inline`
- `ActionFooter`

Temporary exceptions belong in `monsan-ui.consumer-standards.mjs`, but expected final state is no exceptions.

## Important Files

- `src/lib/index.ts`: public package exports.
- `src/lib/monsan-ui.css`: shared app CSS entry.
- `src/lib/variables.css`: tokens.
- `src/lib/components/*`: component library.
- `src/lib/components/icons/*`: shared icons.
- `src/lib/components/questions/*`: exam question controls.
- `src/lib/standards/check-consumer-standards.js`: consumer visual boundary checker.
- `src/lib/standards/check-tooling-standards.js`: suite tooling checker.
- `tests/consumer-standards.test.mjs`: standards test.
- `tests/tooling-standards.test.mjs`: tooling test.
- `src/routes/+page.svelte`: showcase.

## Design Rules

- Prefer semantic components over app-local CSS.
- Keep components accessible by default.
- Preserve keyboard navigation and visible focus.
- Use props for supported variants instead of consumer overrides.
- Avoid one-off styling APIs that only fit one app.
- Keep cards, dialogs, forms, buttons, alerts and navigation visually consistent.

## Package Rules

- Do not commit generated `dist`, `build`, `.svelte-kit` or `node_modules`.
- `dist` is generated by `svelte-package`.
- Consumer lockfiles pin exact MonsanUI commits.
- After MonsanUI changes merge to `main`, consumers must run `pnpm update monsan-ui` and `pnpm test`.

## Commands

```bash
pnpm test
pnpm build
pnpm run build:package
pnpm run lint:package
pnpm run test:standards
pnpm run test:tooling
```

`pnpm test` is the full gate and includes formatting, lint, typecheck, standards, tooling, build, package build and publint.
