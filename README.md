# MonsanUI

MonsanUI is the private Svelte 5 component library used by the Monsan app suite.

Its job is simple: keep Examster, Manki and Owlth visually consistent without forcing each app to redefine layout, spacing, colors, controls, dialogs or common interaction patterns.

## What It Provides

- Styled Svelte 5 components exported from `src/lib`.
- Shared normalize, app base styles and CSS tokens in `monsan-ui.css` and `variables.css`.
- A package CLI that verifies consumer apps do not add local styling.
- A package CLI that verifies suite ESLint, Prettier and tooling standards.
- A local showcase app in `src/routes`.
- Package output generated with `svelte-package`.
- Strict lint, typecheck, build and package validation through `pnpm test`.

## Layout Primitives

Consumer apps should prefer these primitives before adding any app-owned layout CSS:

- `AppShell` for every app page, with optional header, top, bottom and footer regions.
- `AppHeader` and `ContentRegion` for page structure inside the shell.
- `ResponsiveGrid` and `ActionFooter` for repeated layouts and action bars.
- `DataCard`, `StatusPill` and `ConsolePanel` for admin records, status indicators and logs.
- `Background`, `ToastViewport`, `FlashOverlay` and `SkipLink` for app-level visual, feedback and accessibility layers.

## Usage In Apps

Consumer apps install MonsanUI from the private GitHub repository in every environment:

```bash
pnpm add "git+ssh://git@github.com/lucasmonsan/MonsanUI.git#main"
```

Import the shared styles once in the app CSS or root layout:

```ts
import 'monsan-ui/monsan-ui.css';
```

Then import components directly:

```svelte
<script lang="ts">
	import { Button, Stack, Alert } from 'monsan-ui';
</script>
```

Consumer apps must not restyle MonsanUI components. New visual or layout needs should become MonsanUI components or documented props first. See `docs/project-standards.md`.

Consumer apps should run the packaged standards checker:

```bash
monsan-ui-check-consumer
monsan-ui-check-tooling
```

Temporary migration exceptions may be declared in `monsan-ui.consumer-standards.mjs`, but the default and expected state is an empty allowlist.

## Updating Consumers

After changing MonsanUI and merging it into `main`, update each consumer app with:

```bash
pnpm update monsan-ui
pnpm test
```

`package.json` tracks `#main`; `pnpm-lock.yaml` pins the exact commit used by each app.

## Local Commands

```bash
pnpm install
pnpm test
pnpm build
pnpm run build:package
pnpm run lint:package
pnpm run test:standards
pnpm run test:tooling
```

`pnpm test` is the full gate:

```bash
pnpm lint && pnpm typecheck && pnpm run test:standards && pnpm run test:tooling && pnpm build && pnpm run build:package && pnpm run lint:package
```

## Generated Files

Do not commit generated output:

- `build`
- `dist`
- `.svelte-kit`
- `node_modules`

`dist` is generated by `prepare` when consumer apps install the package.

## Environment

MonsanUI does not require a `.env` file.

## Deployment

The showcase is a static SvelteKit app. In Coolify, use the static output generated by the build. Consumer apps must have GitHub/SSH access to this private repository during install.

## Before Merging

Run:

```bash
pnpm test
```
